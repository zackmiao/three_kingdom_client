> 视角固定为「我」（屏幕底部那张 compact 主视角武将卡）。每个客户端看到的内容**只由自己收到的协议包 + 日志文本**决定，因此同一张牌在三种关系下表现不同。
> 依据：`G:\desk\Three_Kingdom_Client\lib\views\game_room_screen.dart`（下文简写 `G`）、`components\*.dart`、`services\audio_service.dart`，以及服务端 `G:\desk\Three_Kingdom\src\main\java\com\threekingdom\engine\handler\*.java`（简写 `S:handler`）。

### 0.1 一张牌打出后，通用管线（约 70% 的表现来自这里）

1. 服务端先发 `BROADCAST_MSG` 文本 → 客户端 `_parseBroadcastLog` 做正则特判，再原样进日志（`G:273-277`）。
2. 服务端再发结构化 `CARD_PLAYED` → `_handleCardPlayed`（`G:433-551`）：
   - `playCard(cardName)` 实为恒播 `play` 音效（`audio_service.dart:110-112`，牌名被丢弃）；
   - 中央结算区 push 一张牌，光束**按目标逐个点亮、间隔 120ms**（`G:491-496`）；
   - 出牌者席位 → 中央飞一张 86×122 的牌（任何人出牌都有，`G:519-540`）；
   - 杀类且有目标 → 中央下方「等待 X 响应【闪】…」胶囊 2600ms（`G:497-501`）；
   - targetIds 含我 → **整桌套 5px 红框**（`G:3094-3105`）；
   - 南蛮/万箭/桃园 → 顶部横幅 1700ms（`G:503-514`）。
3. 响应阶段打出的牌（闪 / 无懈 / 决斗续杀）服务端**不发** `CARD_PLAYED`，客户端退化为**文本猜牌**：日志含「使用了/打出/装备了」+ 30 项牌名白名单 → 中央追加一张牌，3.4s 后消失；**若距上次 `CARD_PLAYED` 不足 800ms 则整段跳过**（`G:1034-1105`）。
4. 席位上的一切反馈（飘字/闪红/爆点/印章/「斩！」）都**只由日志正则**触发（`G:891-1124`、`G:1170-1237`），落点取「日志里最先出现的名字」（`G:1150-1167`）。
5. 音效全集只有 11 个：`play/draw/damage/heal/shield/judge/click/turn/win/lose/skill`（`audio_service.dart:29-32`）。

### 0.2 手牌置暗（只影响我自己的手牌，`G:2246-2310`）

| 场合 | 规则 |
|---|---|
| 弃牌阶段 | 全亮（不置暗） |
| 选了主动技 | 基本不置暗 |
| 响应阶段 | 提示含 `【闪】` → 只亮闪（龙胆含杀类、武圣含红牌）；含 `一张【杀】`/`打出【杀】` → 只亮杀类；含 `【桃】` → 桃（提示含 `【酒】` 时酒也亮）；含 `【无懈可击】` → 只亮无懈；**其余提示一律不置暗** |
| 我的出牌阶段 | 闪、无懈恒暗；桃仅在 `hp<maxHp`；杀类需 `_shaLeft>0`；酒需 `_shaLeft>0 \|\| hp<maxHp`；其余全亮 |

#### 闪（SHAN）
- 自己出牌阶段**恒置暗**，服务端也只在其被响应时才接收。
- 中央是否出现「闪」取决于文本猜牌（800ms 门槛）。
- **「已 抵 消」印章只在 `✔ …躲避了攻击！`（`S:CombatResolver.java:305`）时出现**，1400ms；同时席位飘「已抵消」+ `shield` 音效 + 光束立刻消失。

| 日志 | `★ 我 使用【桃】，回复 1 点体力 (HP: 3/4)` | `❤ A 使用了 桃，为 我 回复 1 点体力 (HP: 1/4)` | 同 |

#### 酒（JIU）
- 中央「酒·X 对 X」，**光束 from==to 不可见**（缺陷 D6）。
- 席位：醉意=暗金边框光晕（`table_seat_card.dart`），我自己还能看到手牌【杀】右上「伤害+1」角标。

- 规则：**一瓶酒只让下一张【杀】+1**，且被【闪】掉也消耗。

## 5. 需实机确认（读代码无法定论）

1. from==to 的退化光束（桃/酒/无中生有/闪电）肉眼是否可见。
2. 「已 抵 消」印章 1400ms 与中央牌 3400ms 的叠加观感。
3. 多人同时飘字/爆点时是否重叠遮挡（`_spawnBurst` 找不到人时回退到自己席位）。
4. 800ms 门槛在真实网络 + AI 停顿下是否吞掉闪/无懈的中央牌（D12）。
5. 八卦阵红判是否给人「已抵消」的错觉（无印章，只有飘字）。
6. 决斗「手牌全亮」的实际误导程度（D1 已由代码确认成立）。
7. 铁索横置在席位卡上的标记样式是否够醒目。
8. 判定弹窗（modal）在我正选目标时弹出会不会挡住操作。
9. 三种响应提示串（`打出 1 张【杀】` / `一张【杀】` / `【闪】`）的真实手感差异。
10. 日志颜色优先级：`★ 我 使用【桃】，回复 N 点体力` 同时含 `★` 与「回复」，实际取哪条规则。

## 6. 一句话总结

- **V1（我出牌）**：中央一张牌 + 与牌种匹配的彩色光束 + 出牌飞行 + `play` 音效 + 金色日志；结算细节全靠服务端**纯文本**驱动飘字/闪红/爆点/印章；只有亲手操作时才会有选目标/选牌弹窗。
- **V2（AI 对我出牌）**：与 V1 同构，但**整桌套 5px 红框**、光束终点变成底部主视角点、席位反馈落在我自己的卡上、我进入响应阶段（手牌大量置暗）。
- **V3（AI 对 AI）**：**几乎没有弹窗**（除判定/五谷/无懈询问）也没有红框；且凡涉及「看别人的牌」的动作（过河拆桥/顺手牵羊/火攻弃牌）**我只能看到牌背**，牌名只在日志里。
